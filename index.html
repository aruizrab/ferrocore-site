3GPP Release 17 · 5G Core · written in Rust

A 5G Core that turns every run into a dataset.

ferrocore runs the 5G core network functions together with a simulated RAN of gNBs and UEs, records every message, state change and fault as labelled, reproducible data, and lets LLM agents observe and act on a live core. It is built for R&D and ML / LLM-agent training, not for production traffic.

See live progress Explore the architecture

Early development. Milestone M0 (foundations) is underway; the network functions are not available yet.

  • Bit-for-bit reproducible from scenario + seed

  • MCP + gRPC control for agents

01

What it is

A research core, deliberately not a production one

ferrocore runs the core network functions of a 5G system (AMF, SMF, UPF, AUSF, UDM/UDR, NRF, PCF and NSSF, with NWDAF and NEF later) alongside an in-tree simulated RAN of gNBs and UEs.

Every run is a dataset: per-interface pcapng that Wireshark decodes, event tables in JSONL and Parquet, KPIs named after TS 28.552, ground-truth label tables and a run manifest. The same scenario, seed and version give the same bytes, every time.

A northbound control API (gRPC and REST) and an MCP server let LLM agents read state and take actions on a live core, from operator changes to injecting faults, spawning UEs or forking a snapshot.

Built for

  • Telecom R&D

    Exercise procedures, mobility and faults on a core you can pause, step, snapshot and fork.

  • ML and data work

    Labelled, reproducible datasets with ground truth for faults and misbehaving UEs, plus KPI time series.

  • LLM agents

    MCP tools, a Gym-style reset/step wrapper and an LM corpus exporter for next-message, masked-IE, cause-prediction and RCA Q&A tasks.

  • Interop testing

    A realtime mode with real N2 and N3 so UERANSIM, PacketRusher and srsRAN can attach.

Out of scope, on purpose

  • Production traffic and HA
  • Charging
  • Lawful interception
  • Roaming
  • SMS
  • RRC / PHY fidelity
  • External DB backends
  • Conformance certification

02

Capabilities

Design decisions the core is built against

ferrocore is early. These are the decisions every crate is held to; the tag on each card is the milestone where the capability lands.

  • Sans-IO network functions

    Every NF and simulated node is a pure, deterministic state machine: handle(input, &mut Ctx). Clock, timers, randomness, outbound messages and events come through Ctx; no I/O, async runtime, wall clock or global state inside NF crates. All state is serialisable for snapshot, fork and restore.

    M0 foundation

  • One codebase, three modes

    sim: all NFs and the RAN in one process on virtual time, faster than real time and bit-for-bit reproducible. run: wall clock with real N2 (SCTP 38412) and N3 (GTP-U UDP 2152). distributed: one container per NF, SBI over HTTP/2, NRF discovery, PFCP over UDP 8805.

    sim M1 · run M3 · distributed M4

  • Real bytes on every interface

    Genuine NAS (TS 24.501), NGAP with ASN.1 APER (TS 38.413), PFCP (TS 29.244), GTP-U (TS 29.281) and 5G security (TS 33.501, TS 35.206), checked by independent oracles: tshark decodes with no malformed packets, re-encode byte equality and a differential codec.

    codecs M0 · procedures M1+

  • Simulated RAN in-tree

    Lightweight gNB and UE state machines with UE profiles (device class, slice, mobility, traffic, misbehaviour), a TR 38.901-style radio model (path loss, RSRP/SINR, A3 events) driving Xn and N2 handover, and real GTP-U for a sampled subset of UEs.

    M1 · mobility M2

  • Every run is a dataset

    A per-scenario event bus carries every message on N1, N2, N3, N4 and SBI, every state transition, timer, KPI tick, fault and agent action as a typed event with causal links. Hooks can observe, mutate, delay or drop. A manifest records scenario hash, seed, commit and checksums.

    bus M0 · KPIs, labels M2

  • Agent control plane

    gRPC, REST and MCP expose read state, operator actions (config, policy, handover, scale or restart) and scenario actions (inject fault, spawn UEs, pause, step, snapshot, fork), separated by role, policy-checked and written to a hash-chained audit log.

    M3

  • Scenarios as one YAML file

    A schema-validated document describes topology, UE populations, a timeline of events, faults and config changes, capture settings, a stop condition and the seed. Scenario plus seed plus version is the whole experiment.

    M1

  • Hardened by default

    No unsafe, every parser fuzzed, dependency and advisory checks, constant-time MAC and RES compares, zeroised keys and secrets redacted from datasets and logs. Malformed input is a dataset feature, never a crash.

    every milestone

04

How it is built

Anchored in the specs, written by agents, checked by oracles

Built almost entirely by AI agents through a spec-driven workflow.

Agents do not work from memory of the standards. Each feature starts from pinned 3GPP Release 17 clause text, becomes testable requirements, and only then becomes code. A human orchestrator acts as product owner and approves what ships.

  1. 01

    Specify

    Requirements in EARS form, each keyed to the clause it comes from.

  2. 02

    Critic

    A spec critic hunts for gaps and ambiguity.

  3. 03

    Approve

    The orchestrator signs off on the spec.

  4. 04

    Plan

    Design and tasks, split into waves with file ownership.

  5. 05

    Tests (red)

    A separate test author writes failing tests first.

  6. 06

    Implement

    Parallel implementers in git worktrees, wave by wave.

  7. 07

    Gates

    fmt, clippy, tests, doctests, trace, deny, audit, tshark.

  8. 08

    Review

    Spec-compliance, security, test-adequacy and performance reviewers.

  9. 09

    Verify

    Two sceptic verifiers try to refute each blocking finding.

  10. 10

    Finalize

    Review record, status Implemented, trace check passes.

  11. 11

    Merge

    The orchestrator merges: the human-in-the-loop approval point.

Traceable to the clause

Requirement IDs carry the specification clause they come from, or a project area such as OBS, SIM, SEC or PERF. Code and tests point back at them, and the trace check fails any mandatory requirement of an approved spec that lacks an implementation site and a passing test.

// illustrative
#[fc_trace::implements("TS24501-5.5.1.2.4-R03")]
fn on_registration_request(...) { ... }

#[fc_trace::verifies("TS24501-5.5.1.2.4-R03")]
fn rejects_when_...() { ... }

Independent oracles

Nothing is correct because an agent says so. Encoded bytes are judged by tools that share no code with the encoder.

  • tshark decodes every capture with no malformed packets or expert errors
  • decode then re-encode must reproduce the original bytes
  • a differential ASN.1 codec cross-checks NGAP
  • interop runs against UERANSIM and PacketRusher

Principles every change follows

  • Sans-IO network functions; no unsafe
  • No panics on untrusted input
  • Tests first, written by a different agent than the code
  • Constant-time crypto compares, secrets redacted
  • O(message) work, ≤ 16 KiB idle state per UE
  • A typed event for everything
  • Small tasks, around 400 changed lines
  • One error enum per crate

Agent roles

  • orchestrator (product owner)
  • spec-author
  • spec-critic
  • architect-planner
  • test-author
  • implementer
  • integrator
  • spec-compliance-reviewer
  • security-reviewer
  • test-adequacy-reviewer
  • perf-reviewer
  • verifier
  • interop-tester

Roadmap

Six milestones, from foundations to a public release

The critical path to the first vertical slice runs through the workspace, the scheduler, the event bus, capture and NGAP, NG Setup, registration, the CLI and the container image.

  1. M0

    Foundations

    Now

    Workspace, gates and CI, core types, the sans-IO runtime and scheduler, the event bus and hooks, capture, codec and crypto facades, and the SBI message layer.

    F001–F008, F017, F018

  2. M1

    Vertical slice in sim

    NG Setup, initial registration with SUCI, 5G-AKA and security mode, a PDU session through SMF and UPF over PFCP, and deregistration for N UEs across M gNBs, with pcapng, JSONL, a manifest, scenario YAML and a Docker image.

    F009–F016

  3. M2

    Mobility and behaviour

    CM-IDLE, service request and paging, periodic and mobility registration, the radio model, Xn and N2 handover, UE profiles and traffic, misbehaviour, fault injection with labels, KPIs and Parquet.

    F019–F031

  4. M3

    Agents and scale

    Control API and MCP server, snapshot and fork, the Gym wrapper, 100k UEs, campaigns on Kubernetes, realtime mode with UERANSIM and PacketRusher interop, and the LM corpus exporter.

    F032–F040

  5. M4

    Distributed and exposure

    OpenAPI code generation, SBI over HTTP/2, NRF, distributed mode, AMF and SMF event exposure, an NWDAF subset, a Kubernetes operator, EAP-AKA′, an XnAP wire codec and distributed fault injection.

    F041–F050

  6. M5

    Visibility and public release

    A progress metric published by CI, this landing page, the licensing work needed before the source goes public, and an interactive front end.

    F051–F054
